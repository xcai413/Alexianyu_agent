# 上线前验收目标

用户于 2026-10-10 要求设定目标并逐项处理；恢复后按本清单推进。基线问题与最初证据见 `生产上线评估.md`，各阶段执行结果记入 `验证记录.md`。

## 完成标准

上线前验收完成必须同时满足：目标环境明确、适用门槛均有当前版本证据、发布版本可追溯、未验收能力关闭，并完成真实交易与恢复／长稳验收。代码实现、离线测试、真实平台验收分别记录；不能用一类证据代替另一类。

本目标不包括发布生产。真实外发使用专用测试对象与已有授权范围，不对普通买家或订单自行发起动作；中断服务的演练在维护窗口进行，运行中的 soak 只读状态、不重启、不干扰。真实 soak 的运行标识、开始时间与环境状态不写入仓库。

## 第一阶段实施边界

G1 在 canonical `domain/message/rules.py` 的共享查询处限制当前账号／全局，CLI、API、旧模块别名和回复引擎共同使用该实现。

G2 使用数据库保存已验证会话的 SHA-256 摘要和到期元数据，不存 Cookie／CSRF 原文、不更换管理员密码或签名密钥。撤销摘要保留，不依据任一实例墙钟自动清理，以避免时间偏差或回拨重新放行会话。SQLite 重复提交采用原子插入，其他数据库沿用唯一键冲突处理，正式远程后端验收另行执行。

新增迁移为 `8c72af19b630`；在临时数据库从前一 head 自动生成并做升级／降级往返。当前真实开发数据库与已运行 Web 服务尚未应用这次迁移和后端代码，不能把隔离回归写成正在运行服务已经验收。部署时必须先升级数据库，并确保所有实例更新；旧版本实例没有撤销检查。

G3 保持订单客户端的只读约束，仅把方法契约对齐至已存在的精确订单读取能力。第一阶段没有新增平台写接口或实际向买家发送消息。
