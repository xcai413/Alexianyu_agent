# Web 运营后台 UI 设计规格

> 状态：待评审。本文只定义界面、交互和数据呈现边界，不代表其中所有接口已实现。
>
> 设计基准：人类与 Agent 共治、单管理员、本地优先。参考图只用于视觉方向，不复制任何外部产品源码或品牌资产。

## 1. 目标与边界

后台服务于正在运营闲鱼账号的人：先发现需要人处理的风险，再完成受控操作，最后能追溯发生过什么。它不替代 CLI、MCP 或 TUI；三者使用同一应用服务和数据源。

首版不提供滑块破解、验证码绕过、设备指纹伪造，也不把真实发货、删除商品、自动外发等高风险操作设计成单击即执行。此类动作必须展示影响范围、要求显式确认，并写入审计日志。

## 2. 信息架构

左侧主导航固定为九项：

| 页面 | 路由 | 用户要完成的事 | 首版数据状态 |
|---|---|---|---|
| 概览 | `/dashboard` | 判断系统是否需要介入 | 可实现摘要；其余卡片待接口补齐 |
| 账号 | `/accounts` | 查看登录态、连接、风险，启动或暂停账号 | 基础读取可实现；操作待受保护接口 |
| 消息 | `/messages` | 处理会话、查看回复决策与人工接管 | 消息读取可实现；会话操作待接口 |
| 商品 | `/items` | 查询镜像、同步、查看详情和生命周期建议 | 读取与同步接口已存在 |
| 订单 | `/orders` | 查询订单、同步、进入发货处理 | 读取与同步接口已存在 |
| 库存与发货 | `/inventory` | 查看卡密余量、预警及交付记录 | 卡密读取可实现；库存聚合待接口 |
| 自动化 | `/automation` | 管理规则、查看规则测试结果 | 规则读取和写入接口已存在 |
| 运行状态 | `/runtime` | 查看 daemon、账号池、多副本健康与租约 | 账号池读取可实现；实例详情待接口 |
| 审计日志 | `/audit` | 检索人工和系统动作 | 待专用读取接口 |

登录页独立于后台壳层，路由为 `/login`。未认证访问任何后台路由时，先检查会话并转回登录页；API 返回 401 时同样回到登录页并显示“登录已失效”。

## 3. 整体视觉系统

### 3.1 布局

- 桌面最小宽度 1180px；左栏宽 248px，顶栏高 70px，内容区最大宽度不设死值。
- 内容区使用 24px 外边距和 20px 栅格间距；页面标题、说明和操作放在同一页首区域。
- 左栏常驻品牌、导航、本机运行提示和版本号；主区不重复放大品牌。
- 顶栏从左到右是全局搜索、运行环境标签、通知入口、管理员菜单。首版搜索只显示为禁用的“即将提供”，不伪造跨资源搜索结果。

### 3.2 色彩与字形

| 用途 | 值 |
|---|---|
| 画布 | `#F8FAFC` |
| 面板 | `#FFFFFF` |
| 主文字 | `#13233A` |
| 次级文字 | `#64748B` |
| 分割线 | `#E5EAF1` |
| 主操作与选中态 | `#1769E8` |
| 正常 | `#16A34A` |
| 待处理 | `#D97706` |
| 风险与失败 | `#DC2626` |

采用系统中文字体优先级：`Inter, PingFang SC, Microsoft YaHei, sans-serif`。页面标题 28px/700，区块标题 16px/650，正文 14px/400，表格与辅助文案 13px。卡片圆角 10px，边框 1px；只允许轻微阴影用于浮层，普通卡片不使用渐变。

状态不只依赖颜色：每个状态同时配中文标签和形状稳定的状态点/徽章。例如“在线”“需验证”“已暂停”“失败”。

### 3.3 基础组件

| 组件 | 行为 |
|---|---|
| 状态徽章 | 固定色义：绿=正常、黄=需关注、红=阻断、灰=未知/停用；带文字 |
| 指标卡 | 标题、主数值、趋势或说明、点击后的明确去向；无数据则显示 `—` 与原因 |
| 数据表 | 表头固定、行高 48px、悬停高亮、分页或“加载更多”；操作集中在末列 |
| 筛选条 | 账号、状态、时间范围、关键词；变更后 URL 查询参数同步，便于复制链接 |
| 空态 | 说明当前为什么为空，以及唯一的下一步，例如“尚未同步商品｜去同步” |
| 错误态 | 明确失败资源与重试按钮；不暴露 Cookie、Token、堆栈或数据库连接串 |
| 受控操作弹窗 | 描述影响对象、不可逆性、审计记录和确认短语；默认焦点不落在确认按钮 |
| 侧边详情 | 用于消息、订单、商品的快速查看；保留列表上下文，支持 URL 直达 |

## 4. 页面规格

### 4.1 登录

白色单列卡片置于浅灰背景。显示产品名“闲鱼运营助手”、副标题“本地运营控制台”、管理员密码输入框、登录按钮和环境提示。

- 提交时按钮进入 loading，密码框不可编辑，避免重复请求。
- 登录失败只提示“密码错误或会话配置不可用”，不区分账号、密码或密钥缺失的内部细节。
- 登录成功后进入原目标页；页面只在 `sessionStorage` 保存 CSRF token，认证会话保留在 HttpOnly Cookie。
- 不提供“记住密码”“找回密码”或第三方登录。

### 4.2 概览

页面首行显示“运营概览”、最近刷新时间和“刷新数据”按钮。四张指标卡按如下顺序排列：

1. 在线账号：`在线 / 启用`，点击进入账号页并筛选异常账号。
2. 待处理消息：未人工接管且未完成处理的入站会话数；接口未完成前显示“数据接入中”，不能显示虚构数量。
3. 今日订单：按本地订单镜像当天创建时间统计；没有同步记录时提示“尚未同步订单”。
4. 库存预警：低于阈值的库存项；阈值或聚合未实现时显示“待配置”。

主区采用 `7:5` 两列：左侧“最近动态”和“待处理异常”，右侧“最近订单”。右边窄栏为“快捷操作”与“系统状态”。

- 最近动态只显示真实审计、消息、订单和运行事件，并带来源和时间。
- 待处理异常按严重级排序：需人工验证、账号离线、回复失败、库存不足、同步失败。
- 快捷操作首版只开放无副作用的“同步商品”“同步订单”“刷新状态”；涉及暂停自动回复、Token 刷新时先进入确认弹窗。
- 所有卡片在首次载入使用骨架屏；刷新采用 180ms 淡入，不使用数字滚动动画。

### 4.3 账号

上方提供“添加账号”“扫码登录”和状态筛选。表格列为：账号、备注、启用状态、期望状态、实际连接状态、最后心跳、风险、当前所有者、操作。

点击行进入右侧详情：Cookie 是否存在（仅显示“已配置/未配置”）、Token 有效期、熔断信息、最近错误、租约与接管记录。任何凭据只显示脱敏摘要，绝不回显完整值。

“启动”“暂停”“重新认证”“允许接管”都属于受控操作；启动/暂停显示账号范围，重新认证跳转扫码流程，接管要求展示当前 owner 和租约失效时间。

### 4.4 消息

采用三栏：会话列表、消息时间线、会话/回复决策详情。窄屏降级为列表页与详情页两级。

- 会话列表显示买家、关联商品、最后消息摘要、未读或待处理状态、人工接管状态。
- 时间线严格区分入站、人工发送、自动回复、系统事件；自动回复显示规则或 AI 决策摘要和安全闸结果。
- 右栏可执行“人工接管”“恢复自动回复”“添加商品级回复”。外发回复必须放在后续受控版本，首版只读展示。
- 新消息以顶部非阻塞提示进入；用户正在阅读其他会话时不自动跳转。

### 4.5 商品

列表提供账号、在售状态、价格、已售、最近同步、生命周期建议与操作。页首“同步商品”是受控异步任务：按钮进入进行中，完成后刷新表格并显示结果摘要。

详情侧栏展示商品基本信息、规格绑定、库存来源、最近回复活动保护期和生命周期判定理由。“下架/删除”始终进入二次确认，并区分“建议”和“已执行”。

### 4.6 订单

列表支持账号、状态、时间范围和关键词筛选。列为订单号、商品、金额、数量、买家、下单/付款/发货时间、状态、操作。

订单详情展示本地镜像字段、关联库存预留与发货状态。没有远端确认的字段应明确标为“本地镜像”，不得显示为平台已确认。同步是受控读取操作；发货动作需单独确认并展示将消耗的卡密项。

### 4.7 库存与发货

上半区显示库存总览、低库存预警和库存变更；下半区显示待交付、交付中、已交付、失败的订单队列。卡密正文只显示数量、类型、启用状态及脱敏预览；默认不展示完整卡密。

补货使用粘贴/导入确认页，先解析、预览条数和重复项，再提交。手动消耗和发货都要求确认短语，并在成功后打开对应审计记录。

### 4.8 自动化

规则页包含规则列表、状态、优先级、作用账号、匹配条件、回复文本预览和最近命中次数。新增和编辑放在侧边表单内，规则测试在本地显示“输入内容 → 命中规则 → 预计输出”，不会发送任何消息。

系统级“紧急停止自动外发”放在醒目但不误触的位置：启用后页面顶栏持续显示红色状态条，所有自动外发入口禁用并解释原因。

### 4.9 运行状态

顶部展示当前环境、数据库连通性、迁移版本、daemon 实例数和整体健康。实例表展示实例 ID、版本、运行时间、心跳年龄、拥有账号数、最后错误；账号池表展示期望与实际状态、重连数、租约和风险。

对多副本状态必须直白呈现“当前 owner”“租约到期时间”“是否发生漂移”。页面只观察和引导，不在首版提供强杀、重启或随意接管按钮。

### 4.10 审计日志

按时间倒序展示主体（管理员/系统/Agent）、动作、对象、结果、原因和关联资源链接。支持账号、动作类型、结果和时间范围筛选。详情显示结构化、脱敏后的上下文；禁止直接渲染原始异常堆栈或秘密字段。

## 5. 前端交互与动效

- 路由切换：内容区 120–160ms 淡入/位移 4px；用户启用“减少动态效果”时取消。
- 按钮：hover 仅改变背景与边框，loading 显示小型旋转指示，不位移整体布局。
- 表格和卡片：hover 使用浅蓝灰底；可点击元素必须有键盘焦点环。
- Toast：右上角堆叠，成功 4 秒自动收起；错误需手动关闭并保留“重试”。
- 抽屉和弹窗：200ms 淡入；按 Escape 关闭非破坏性弹窗，确认弹窗必须保留取消路径。
- 轮询：概览和运行状态默认 30 秒，浏览器标签页不可见时暂停；手动刷新可用。不会用前端轮询触发平台写操作。

## 6. 响应式与可访问性

- `>=1180px`：完整三栏或两栏布局，左栏固定。
- `768–1179px`：左栏收为仅图标（仍有可访问名称），右侧详情改抽屉。
- `<768px`：左栏变底部导航，数据表转为可展开卡片，消息三栏转为单页堆栈。
- 所有关键状态同时给文字；对比度至少达到 WCAG AA；键盘可覆盖导航、筛选、表格、抽屉和弹窗。
- 时间统一显示本地时区和绝对时间；短时间可辅助显示“3 分钟前”，但不只显示相对时间。

## 7. 实施顺序与验收

### UI-1：壳层与设计令牌

实现登录页、后台壳层、左栏、顶栏、路由、空态、错误态、骨架屏与响应式断点。验收：无认证访问受保护路由会跳转；刷新任意 SPA 路由仍能加载应用。

### UI-2：概览、账号、运行状态

先连接已有受保护摘要、账号、账号池 API；未有数据的区块明确显示接入状态。验收：不产生真实闲鱼写操作，且页面数值与 CLI/数据库镜像一致。

### UI-3：消息、商品、订单、库存

按已有只读/同步能力逐页接入；每个写操作先完善受保护 API、审计和确认流程再开放。验收：同步结果、筛选和详情均能由真实本地镜像复核。

### UI-4：自动化、审计、全局风险条

接入规则、人工接管、紧急停止和审计。验收：操作成功/失败均有可检索审计记录；不展示秘密信息。

### UI-5：视觉与浏览器验收

在 Chromium 对桌面与窄屏截图检查，验证键盘路径、加载/空/错误/确认状态。真实闲鱼验证项目写入 `docs/待真实验证清单.md`，不在本地模拟中伪称通过。

## 8. 与当前实现的差距

当前仅具备静态壳层、管理员会话基础、受保护概览摘要和少数路由占位。本文列出的完整导航、真实列表数据、统一错误契约、SPA 深链接回退、受控操作、审计读取与浏览器视觉验收均尚未完成。因此接下来应先按 UI-1 完成完整壳层和可视状态，再按页面接入后端能力。
