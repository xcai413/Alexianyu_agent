## P0.3 Windows 启动与自恢复(2026-08-14)

- 实现 `service install/start/stop/status/uninstall`,以安装时解析的绝对 `pythonw.exe` 和工作
  目录创建隐藏的 `XianyuAgent-Daemon` 主任务。
- 初版只配置主任务 `RestartOnFailure`;真实强杀 PID 后任务停在 Ready 且结果为
  `0xFFFFFFFF`,100 秒内没有恢复。该失败被保留,未按通过处理。
- 根据失败证据增加 `XianyuAgent-Watchdog`:独立 TimeTrigger 每分钟运行,结合数据库状态、
  90 秒心跳和 PID 判断 daemon 健康,异常时重新运行主任务。
- 修复首次双任务并发时 Watchdog 误杀 `starting` daemon 的竞态;新鲜的 starting/stopping
  实例不再被终止,只有 stale 的存活实例才进入结束与重启路径。
- 增加 `data/runtime/service.paused` 人工暂停门;`service stop` 后等待 70 秒,
  `SERVICE_RUNNER_COUNT=0`,确认不会被 Watchdog 误拉起;随后 `service start` 恢复 online。
- P0-C 真实验收:强制结束旧 daemon PID `2620`;Watchdog 下一分钟执行成功,有效 daemon
  恢复为 PID `19816`,`xcaicai` 恢复 connected,总耗时小于 75 秒且只有一个有效 daemon。
- 当前环境采用 `--startup user`,两个任务均已安装;`demo` 因无正式 Cookie 已停用,
  `xcaicai` 保持 `enabled + desired_state=running`。
- 最终检查:`uv run ruff check .`、`git diff --check` 通过;
  `uv run pytest -q` → **163 passed**。

边界:P0-D Windows 重启尚未执行;P0-A、P0-B 与 P0-E 长稳验收也仍待完成。
