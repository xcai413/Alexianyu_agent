## 实现边界

- 继续使用选定方案 1 的黄色主操作和浅色界面；本轮参考功能组织，不做逐像素复制。
- 消息历史 API 增加可选 `chat_id`，复用 CLI 使用的已有领域查询。账号与会话先过滤，再取最近记录；鉴权边界保持管理员会话。
- 读取 Hook 识别当前请求路径并丢弃已取消的响应，切换会话或账号时不展示上一范围的数据。
- 搜索限定已加载列表；消息为本地镜像，打开会话不触发平台已读上报。未接管不能发送，接管与回复沿用既有确认及 CSRF 校验。
- 商品、发货、自动化标签只调整现有功能位置。没有新增平台协议、设置写入能力、账号角色或依赖。

## 第三阶段：订单详情与发货配置流程

2026-10-10，继续沿用方案 1、参考订单页的状态／搜索层级和配置页的表单／状态分区模式。本阶段不新增依赖、路由或后端能力。

- 订单改为列表与详情双栏，手机上下排列；显示金额、数量、时间和当前账号的本地发货任务。订单镜像状态与任务状态分开，缺失标题／日期保持缺失。摘要和搜索只针对已加载窗口。
- 详情到发货区携带账号及订单号；账号不匹配时弃用预填。发货区由预演与任务记录组成，任务支持搜索／状态筛选，结果不明仍需填写依据后人工核销／退回。
- 预演绑定当前订单，换单清空；预演开始和执行／收尾后旧结果失效。忙状态禁止修改目标与重复提交，真实发货保留订单号确认、CSRF 与后端再次检查。提前被守卫阻止时，配置显示“未返回策略／未评估”，不把默认值当作已作出的配置决策。
- 发货配置拆成发卡源、库存池、发货策略三步，编辑与目录并排；密钥保存按需展开，试调用明确为真实外部请求。分区内切换保留草稿，库存池可带池 ID 进入策略表单；商品入口默认进入策略分区并带商品 ID。
- 库存池目录包含当前账号及全局范围，策略目录只列账号专属策略；最终策略选择仍以预演为准。待人工处理单独按当前账号读取，交付镜像独立标签，卡密与模板入口保留。
- 手机横向标签栏在切换或宽度变化后自动露出当前标签；表单和卡片按窄屏折行，交付宽表只在自身区域横滚。

## 第四阶段：库存池、卡密导入与发货模板

- 库存入口以发货库存池为默认目录，原有库存卡保留独立标签；摘要、类型／状态搜索、列表／详情集中展示，逐条卡密池可带当前账号和池 ID 跳转到导入或策略配置。API／固定文案不计入卡密余量，关联策略以最终发货预演为准。

- 模板编辑／全局目录分栏，支持载入草稿、名称与正文搜索、启用筛选；正文预览仅检查排版，变量不替换。同名保存会覆盖并启用，按钮明确提示，失败保留草稿；目录长名称折行，正文内部滚动，窄屏上下排列。
